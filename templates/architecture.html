Registration Execution Flow

[User Input] ➔ [WTForms Validation] ➔ [Salt Gen (16B)] ➔ [Argon2id Hash] ➔ [Kyber-512 Keypair] ➔ [BLAKE2b Commitment C_q] ➔ [MySQL Persistence]
  1. Form Input & Sanitization: Input username, email, and password validated against complexity policy.
  2. Argon2id Hashing: 16-byte random salt generated; Argon2id memory-hard hash ($m=64\text{MB}, t=3, p=4$) computed.
  3. Lattice Key Generation: CRYSTALS-Kyber-512 generates Module-LWE public key ($pk$) and private key ($sk$).
  4. Quantum Commitment Generation: $C_q = \text{BLAKE2b-512}(pk \parallel Argon2idHash \parallel Salt)$.
  5. MySQL Storage: All credentials and keys stored securely with indexed unique constraints.

Authentication & Verification Flow

[Login Credentials] ➔ [Account Lock Check] ➔ [Argon2id Verification] ➔ [Quantum Commitment Verification] ➔ [Audit Log & Session Creation]
  • Lockout Inspection: System verifies if failed_attempts >= 5 or if lock window is active.
  • Argon2id Verification: Plaintext password verified against stored hash in constant time.
  • Quantum Commitment Verification: Re-computes $C_q'$ and compares against DB commitment using constant-time string check to prevent timing attacks.
  • Session Security: Sets 15-minute HTTPOnly, SameSite session cookie and logs client IP & browser in login_history.
